# 设计取舍与边界

本文记录项目里**有意为之**的取舍，而不是待修缺陷。每节写清当前选择、原因、代价与边界，
以及什么情况下值得重新考虑。取舍发生变化时，同步更新本文与相关测试。

## 存档位置

- **选择**：GUI 把工作目录切到可执行文件所在目录，存档库放在可执行文件旁；CLI 跟随启动目录，
  启动时打印绝对路径，并支持 `--db` 指定文件。
- **原因**：计算概论大作业要求项目自包含，不往 AppData 等用户目录写文件；CLI 跟随当前目录
  也符合命令行工具惯例。
- **代价与边界**：GUI 与 CLI 从不同目录启动时可能各有一份 `einstein_save.db`；可执行文件
  位于只读目录时无法保存。
- **何时重新考虑**：做安装包、便携包，或需要多用户隔离时。

## 数据库并发

- **选择**：不设 `busy_timeout`、WAL 或多实例锁；同一时间只允许一个窗口/进程操作存档库。
- **原因**：正常玩法只开一个窗口，跨进程并发不是目标场景；避免为小项目引入额外状态和重试逻辑。
- **代价与边界**：两个进程同时写同一库时会直接报 `SQLITE_BUSY`，表现为“无法打开或读取存档”。
- **何时重新考虑**：需要多开窗口、后台服务或自动保存时。

## AI 执行模型

- **选择**：AI 决策在 UI 线程同步执行；默认搜索档深度 4，无 alpha-beta、置换表和时间预算；
  GUI 用三段过渡延迟（默认值见 `src/ui/gui/views/game_widget.h`）分隔掷骰确认、走子衔接与 AI 思考。
- **原因**：单线程实现简单，局面状态不需要跨线程同步；GUI 本来就要展示“电脑思考中”的节奏。
- **代价与边界**：低端机器上单步可能短暂卡顿；没有硬性时间上限，搜索深度提高后更明显。
  本机 Release 实测单步中位数约 0.8–24 ms（最慢为降级选子），见 [AI 性能基准](BENCHMARK.md)。
- **何时重新考虑**：搜索深度或耗时明显上升，或需要秒级响应时。

## AI 评估模型

- **选择**：用“双方到目标角的竞速到达时间”估计胜率，不设材料价值项，也不显式建模阻挡与占位；
  同分时优先斜向推进。
- **原因**：爱因斯坦棋的目标是到达对角，吃光对方只是达成目标的一种手段；竞速模型与规则目标
  一致，46656 状态表可以预计算。
- **代价与边界**：对阻挡、吃子和战术组合的感知较弱；不是通用棋类评估函数。
- **何时重新考虑**：需要明显提高棋力，或加入更复杂的战术搜索时。

## Toast 提示

- **选择**：绝对定位的临时浮层，只在 `show_message()` 时按父窗口当前位置计算一次坐标。
- **原因**：提示条短命，不值得为它监听父控件尺寸变化、增加 eventFilter 耦合。
- **代价与边界**：窗口在提示显示期间缩放，提示条会停在上一次的位置，直到下一次提示。
- **何时重新考虑**：需要常驻通知栏，或需要跟随布局变化时。

## GUI 的子系统

- **选择**：`einstein_gui` 在 Release 配置下设置 `WIN32_EXECUTABLE`，Debug 保留 Console 子系统。
- **原因**：Release 双击启动不弹出黑色控制台窗口；Debug 保留 `qDebug` 等标准输出的日志，便于排查。
- **代价与边界**：Release 没有控制台，`qDebug` 与 `std::cerr` 的输出会被丢弃；该属性只在 Windows
  链接时生效，其他平台没有这层区别。
- **何时重新考虑**：需要在 Release 收集日志时——应写日志文件，而不是切回 Console 子系统。

构建分支的细节见 [架构说明](ARCHITECTURE.md) 的平台分支。

## CLI 的代码页

- **选择**：`main_cli.cpp` 在 `_WIN32` 下调用 `SetConsoleOutputCP(CP_UTF8)` 与
  `SetConsoleCP(CP_UTF8)`；两者任一失败只打印告警，不终止程序。
- **原因**：Windows 控制台默认代码页通常不是 UTF-8，直接输出中文与棋盘符号会乱码；用 Win32 API
  切换而不是 `system("chcp 65001")`，既不启动子进程，也避免 `chcp` 读走被重定向的 stdin 第一行。
- **代价与边界**：只影响控制台显示，不影响程序写出的字节；重定向到文件时仍是 UTF-8 字节流。
  终端字体缺字时仍可能显示方块。
- **何时重新考虑**：需要支持非 UTF-8 终端，或统一走 `WriteConsoleW` 时。

## Botzone 错误处理

- **选择**：区分 `ProtocolError`（输入或协议问题）与内部异常；stderr 分别打印
  `Botzone 协议错误:` / `Botzone 内部错误:`；stdout 始终输出 `{"response":{}}`，退出码 0。
- **原因**：平台没有明确“非法输入应返回什么”；空 response 表示“本次没有决策”，比伪造一步棋
  或让进程崩溃更安全。
- **代价与边界**：本地调试时错误不够直观；平台可能把空 response 视为本回合失败。
- **何时重新考虑**：平台给出明确错误协议，或需要本地严格模式时。

## 存档格式

- **选择**：文本格式，第一行是标量头（含档位、随机种子与已掷次数），第二行是棋盘；
  读取时做格式、溢出与窄化校验，领域一致性统一交给 `core::validate_state`。
- **原因**：格式小、可读、便于排查；项目没有历史发行版，不保留对缺字段数据的静默兼容；
  把随机流写进存档，读档无需依赖命令行参数。
- **代价与边界**：没有 schema 版本号，字段变化需要显式修改读写两端；缺档位、非法档位、
  缺失随机流字段与布阵阶段的局面都会被拒绝。
- **何时重新考虑**：需要转换数据格式、压缩或存储更多对局元数据时。字段细节见 [存档格式](SAVE_FORMAT.md)。

## 现场快照

- **选择**：GUI 每次状态变化后把局面与随机流覆盖写入 `einstein_scene.db` 的固定槽位 `scene`；
  CLI 不写快照，只读取该文件复现；玩家界面不出现任何相关控件。
- **原因**：GUI 没有控制台，也没有命令行种子记录；出问题的对局若不留下现场，事后无法还原
  骰序与 AI 决策。复用 `SaveManager` 与存档格式，不新增序列化代码。
- **代价与边界**：每次动作多一次小型 SQLite 写入；只覆盖“局面可保存”的时刻，渲染类问题、
  启动即崩溃与目录不可写三种情况留不下快照；快照不是用户存档，不参与存档列表。
- **何时重新考虑**：需要保留多份现场、需要记录玩家输入序列，或写快照的延迟影响操作手感时。

## 平台支持

- **选择**：只在 Windows + MSYS2 UCRT64（GCC 16.2、Qt 6.11）上实测；CI 覆盖 Windows 完整构建、
  无 GUI 构建与 clang-format。
- **原因**：课程环境固定；Qt 与 MinGW 的 ABI 在 MSYS2 UCRT64 下最省事。
- **代价与边界**：Linux/macOS 未做构建验证；其他编译器的告警差异可能触发 `-Werror`。CMake 为
  MSVC 配置了 `/utf-8` 与 `/W4 /WX`，但这只是让它有机会编译，不代表该路径被验证过。
- **何时重新考虑**：需要跨平台发布，或接入 Linux CI 时。
