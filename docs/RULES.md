# 棋盘规则

本文说明本项目采用的 5×5 爱因斯坦棋规则口径。规则以 Botzone 爱因斯坦棋裁判代码为准，
本仓库的判定实现在 `src/core/rules.cpp`，回归用例在 `tests/core_rules_test.cpp`；
两者与本文件冲突时，先核对裁判代码，再同步这三处。

## 1. 棋盘与坐标

- 棋盘 5 行 × 5 列。代码里 `Pos.x` 是行号（自上而下 0~4），`Pos.y` 是列号（自左向右 0~4）。
- 每方 6 枚棋子，编号 1~6 各一枚，编号在整局内跟随棋子本身。
- 红方初始区是左上角 `x + y ≤ 2` 的 6 个格：
  `(0,0) (0,1) (0,2) (1,0) (1,1) (2,0)`，目标角为右下角 `(4,4)`。
- 蓝方初始区与红方中心对称，是 `x + y ≥ 6` 的 6 个格：
  `(4,4) (4,3) (4,2) (3,4) (3,3) (2,4)`，目标角为左上角 `(0,0)`。

布阵阶段双方各自把 1~6 放进自己的初始区，一格一枚。初始区的格子与落位顺序由
`core::Board::start_positions` 的坐标表定义，界面通过 `core::Board::start_index` 查询。

## 2. 回合流程

一个回合由“掷骰 → 选子 → 走子”三步组成：

1. **掷骰**：当前行棋方掷一枚六面骰，得到点数 `N`（1~6）。
2. **选子**：按第 3 节的规则确定本回合可动的编号；候选可能是一枚，也可能是两枚。
3. **走子**：选中的棋子沿第 4 节的方向走一格，落点必须在棋盘内。

走子完成后立即结算：

- 满足第 6 节的胜利条件则对局结束，直接进入结束状态；
- 否则换到另一方，回到“掷骰”阶段，本回合的骰点作废。

布阵阶段双方都确认后，先手固定为红方。

## 3. 掷骰选子

设骰点为 `N`，本方在场编号的集合为 `A`：

1. 若 `N ∈ A`，本回合只能动 `N` 号，候选只有一枚。
2. 若 `N ∉ A`，候选为 `A` 中小于 `N` 的最大编号，以及 `A` 中大于 `N` 的最小编号。
   两侧都可能存在，也可能只存在一侧；只有一侧存在时，候选也只有一枚。
3. 每方 1~6 各一枚，编号不会重复，因此候选最多两枚。

完整骰点表（“其余编号全在场”列给出同号缺席时的典型候选）：

| 骰点 | 同号在场 | 同号缺席（其余全在场） | 候选数量 |
| ---: | -------: | ---------------------- | -------- |
|    1 |        1 | 2                      | 1        |
|    2 |        2 | 1、3                   | 1 或 2   |
|    3 |        3 | 2、4                   | 1 或 2   |
|    4 |        4 | 3、5                   | 1 或 2   |
|    5 |        5 | 4、6                   | 1 或 2   |
|    6 |        6 | 5                      | 1        |

边界例：

- 骰点 3，本方在场 `{1,2,5,6}`：候选 2 与 5，两枚都可动。
- 骰点 3，本方在场 `{1,2}`：候选只有 2。
- 骰点 3，本方在场 `{5,6}`：候选只有 5。
- 骰点 1，本方在场 `{2,3,4,5,6}`：候选只有 2。
- 骰点 6，本方在场 `{5}`：候选只有 5。
- 骰点 4，本方在场 `{4}`：候选只有 4。

## 4. 走子方向

每枚棋子每步只能沿本方的三个前进方向走一格：

| 阵营 | 方向（行增, 列增）               | 文字描述           |
| ---- | -------------------------------- | ------------------ |
| 红方 | `(+1, 0)`、`(0, +1)`、`(+1, +1)` | 向下、向右、向右下 |
| 蓝方 | `(-1, 0)`、`(0, -1)`、`(-1, -1)` | 向上、向左、向左上 |

- 一次只能走一格，不存在连走、跳跃或后退。
- 落点必须在棋盘内；越界不算合法着法。
- 落点是否被占据不影响合法性，见第 5 节。

## 5. 吃子

落点上有棋子时，该棋子被覆盖移除，可能是对方的，也可能是己方的：

- **吃己方棋子是合法着法**，不是实现缺漏，也不是本项目添加的变体。
- 因此一方可能主动把自己吃到只剩一枚，甚至吃光；吃光即按第 6 节判负。
- 规则的设计意图是“尽快到达对角”，棋盘上的子力只是移动手段，不需要保持存活。

## 6. 胜负

局面满足下列任一条件即分出胜负：

1. 红方棋子数为 0 → 蓝方胜；
2. 蓝方棋子数为 0 → 红方胜；
3. 红方任一枚棋子位于 `(4,4)` → 红方胜；
4. 蓝方任一枚棋子位于 `(0,0)` → 蓝方胜；
5. 以上都不满足 → 对局继续。

全灭与占角不会指向不同的胜者：一方棋子数为 0 时，棋盘上不可能再有该方的棋子占住目标角；
双方都还有棋子时，全灭条件不成立。因此检查顺序不影响结论——`core::rules::check_winner`
先判全灭，Botzone 裁判代码先判角，同一局面得到相同的胜者。`check_winner` 的结论还会被
`core::validate_state` 用来交叉校验终局存档。
